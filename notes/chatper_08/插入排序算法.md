# 直接插入排序

[可视化前端1](HTML/直接插入排序_chatgpt.html)

[可视化前端2](HTML/直接插入排序_gemini.html)

### 1. 核心运行机制

直接插入排序将整个数组逻辑上分为两个部分：

- **有序序列：** 初始状态下，通常把数组的第一个元素看作是一个长度为 1 的有序序列。
- **无序序列：** 数组中剩下的其余元素。

**排序过程：**

每次从“无序序列”中取出第一个元素，在“有序序列”中从后向前进行扫描。如果遇到比自己大的元素，就把那个元素往后挪一个位置，腾出空间；直到遇到小于或等于自己的元素时，就插入到该元素之后。

### 2. “哨兵”的巧妙作用

在你提供的代码中，有一个非常经典的优化技巧——**哨兵（Sentinel）**，即将 `A[0]` 位置空出来作为暂存区。它的作用有两个：

1. **暂存数据：** 也就是保存当前准备插入的元素 `A[i]` 的值，防止在后续挪动数据的过程中被覆盖。
2. **防止越界（提升效率）：** 在内层循环 `for(j=i-1; A[0]<A[j]; --j)` 中，程序不断向前寻找插入点。如果没有哨兵，我们需要每次都写上 `j >= 1` 的判断来防止数组越界。而加上哨兵后，当 `j` 递减到 `0` 时，必然有 `A[0] == A[0]`，循环自然终止，这省去了一次边界检查，从而在大量数据排序时提升了微小的运行速度。

### 3. 算法性能分析

- **时间复杂度：$O(n^2)$**

  - **最好情况：** $O(n)$。如果初始数据已经排好序（如 1, 2, 3, 4, 5），每次只需比较 1 次，不需要移动元素。
  - **最坏情况：** $O(n^2)$。如果初始数据是完全逆序的（如 5, 4, 3, 2, 1），每次插入都需要比较并移动所有已排序的元素。

- **空间复杂度：$O(1)$**

  算法只需要常数级别（如哨兵和循环变量）的辅助空间，是一种**原地排序算法**。

- **稳定性：稳定**

  在从后往前的比较中，只有遇到**严格小于**当前元素的项才会停止并插入，因此相同大小的元素的相对顺序不会改变。

### 4. 代码

```C++
void InsertSort(ElemType A[], int n){
    int i, j;
    for(i=2; i<=n; i++)              	// 依次插入
        if(A[i] < A[i-1]){           	// 若小于前驱
            A[0] = A[i];             	// 复制为哨兵
            for(j=i-1; A[0]<A[j]; --j) 	// 从后往前查
                A[j+1] = A[j];       	// 向后挪位
            A[j+1] = A[0];           	// 复制到位置
        }
}
```



# 折半插入排序

[可视化前端1](HTML/折半插入排序_chatgpt.html)

[可视化前端2](HTML/折半插入排序_gemini.html)

### 1. 核心运行机制

算法依然将数组分为“有序区”和“无序区”，每次从无序区拿出一个新元素，但在有序区找位置时，做法变了：

- **设定边界：** 设定左指针 `low` 指向有序区的开头，右指针 `high` 指向有序区的结尾。
- **折半比较：** 算出中间位置 `mid`，将新元素与 `mid` 位置的元素进行比较。
  - 如果**新元素 < `mid` 元素**：说明新元素应该插入在左半区，于是把查找范围缩小到左边（`high = mid - 1`）。
  - 如果**新元素 $\ge$ `mid` 元素**：说明新元素应该插入在右半区，把查找范围缩小到右边（`low = mid + 1`）。
- **确定位置并搬家：** 当 `low > high` 时，查找过程结束。此时 `high + 1` 就是新元素该去的确切位置。接着，把 `high + 1` 到原来的位置之间的所有元素统一往后挪一位，把新元素插进去。



### 2. 两个非常容易踩坑的细节

**细节一：为什么遇到相等元素时，还要往右找？（稳定性的奥秘）**

在上面的折半判断中，如果新元素**等于** `mid` 元素，算法并没有停下来，而是执行 `low = mid + 1` 继续在右半区查找。

这是为了保证算法的**稳定性**。遇到相等的元素时，我们必须保证后来者插在原来元素的**后面**，所以哪怕找到了相等的，也要假装没找到，继续向右逼近，直到循环结束，最终插入位置就会正好卡在所有相等元素的最后面。

**细节二：为什么最终插入位置是 `high + 1`？**

当 `low` 和 `high` 错开（即 `low > high`）时，查找结束。由于最后一步要么是 `high` 往左移越过了 `low`，要么是 `low` 往右移越过了 `high`，此时 `high` 指向的元素必然是**最后一个小于或等于待插入元素**的值。因此，待插入元素理所当然应该排在它后面，也就是 `high + 1` 的位置。



### 3. 算法性能分析

- **比较次数减少了：** 查找位置的时间复杂度确实从 $O(n)$ 降到了 $O(\log n)$。总的比较次数降到了 $O(n \log n)$。
- **但移动次数没变：** 找到了插入位置，前面的数据还是得**挨个往后挪**。这部分的移动时间复杂度在最坏情况下依然是 $O(n^2)$。
- **时间复杂度：$O(n^2)$：**折半插入排序的总时间复杂度依然是 $O(n^2)$
- **空间复杂度：$O(1)$：**原地排序，只需要常数级别的辅助空间（如 `low`, `high`, `mid` 和暂存变量）。
- **稳定性：稳定**。

总结来说，折半插入排序是用**折半查找**优化了**比较过程**，但无法优化**移动过程**。它适合于数据量不是很大，且每个元素的比较操作非常耗时（比如对比长字符串）的场景。



### 4. 代码

```c++
Status BinaryInsertSort(ElemType *A, int n) {
    if (A == NULL || n <= 0) return ERROR;
    if (n == 1) return OK;

    int i, j, low, high, mid;
    for (i = 2; i <= n; i++) {
        if (A[i] >= A[i - 1]) continue;

        A[0] = A[i];
        low = 1;
        high = i - 1;

        while (low <= high) {
            mid = (low + high) / 2;
            if (A[0] < A[mid]) high = mid - 1;
            else low = mid + 1;
        }
        
        for (j = i - 1; j >= high + 1; j--)
            A[j + 1] = A[j];

        A[high + 1] = A[0];
    }

    return OK;
}
```



# 希尔排序

[可视化前端1](HTML/希尔排序_chatgpt.html)

[可视化前端2](HTML/希尔排序_gemini.html)

### 1. 核心机制

希尔排序可以理解为：**先让数据大致有序，再进行直接插入排序。**

希尔排序的做法是：先设置一个**增量 gap**，让相隔 `gap` 个位置的元素分成一组，在每一组内部做直接插入排序。

然后缩小增量继续在每一组内部做直接插入排序。

```
gap = 4 → gap = 2 → gap = 1
```

当 `gap = 1` 时，整个序列就退化成一次普通的直接插入排序。但是这时候序列已经比较接近有序了，所以最后一次插入排序会快很多。

希尔排序的核心过程可以概括为：

```
设置增量 gap
↓
把相隔 gap 的元素分为一组
↓
每组进行直接插入排序
↓
不断缩小 gap 并重复组内直接插入排序
↓
直到 gap = 1，完成最终排序
```

也可以记成一句话：

```
先分组粗排，再整体细排
```



### 2. 算法性能分析

##### 1. 时间复杂度

希尔排序的时间复杂度和**增量序列的选择**有关。

如果增量选择得好，效率会明显高于直接插入排序。

常见说法是：

```
最好情况：O(n log n)
平均情况：大约 O(n^1.3) 到 O(n^2)
最坏情况：O(n²)
```

它没有像快速排序、归并排序那样固定的统一时间复杂度，因为不同的 `gap` 取法会影响排序效率。



##### 2. 空间复杂度和稳定性

希尔排序是在原数组上进行排序，只需要少量辅助变量，所以空间复杂度是：

```
O(1)
```

它属于**原地排序算法**，是**不稳定排序算法**。

### 3. 总结

希尔排序的特点可以概括为：

```
核心思想：分组插入排序，逐步缩小增量
排序过程：gap 较大时粗排，gap = 1 时细排
时间复杂度：与增量序列有关，通常优于直接插入排序
空间复杂度：O(1)
稳定性：不稳定
适用场景：中等规模数据，想要比直接插入排序更快
```

一句话理解：

```
希尔排序 = 按增量分组的直接插入排序
```



### 4. 代码

```c++
Status ShellSort(ElemType *A, int n) {
    if (A == NULL || n <= 0) return ERROR;
    if (n == 1) return OK;

    int dk, i, j;
    for (dk = n / 2; dk >= 1; dk /= 2)
        for (i = dk + 1; i <= n; i++) {
            if (A[i] >= A[i - dk]) continue;
            A[0] = A[i];
            for (j = i - dk; j > 0 && A[0] < A[j]; j -= dk)
                A[j + dk] = A[j];
            A[j + dk] = A[0];
        }

    return OK;
}

```
